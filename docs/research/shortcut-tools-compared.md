# skhd vs Raycast vs Karabiner-Elements for Shortcuts

Research for [#110](https://github.com/pnitijarasrat/dotfile/issues/110), part of map [#106](https://github.com/pnitijarasrat/dotfile/issues/106) (Shortcut spec).
Researched 2026-10-12 on this Mac: macOS 14.1, skhd 0.3.9 (Homebrew), Karabiner-Elements 16.3.0, Raycast 1.69.0. Enabled input sources are ABC and Thai.

## TL;DR

- **Karabiner is the most robust layer.** It works under Secure Keyboard Entry, which its own feature list states. It has a native open-or-focus (`software_function.open_application`), a native input-source switch (`select_input_source`), real per-app conditions, and variables for modes. Its config (`karabiner/karabiner.json`) is already in this repo. The downside is JSON verbosity.
- **skhd has the best DSL for modes and shell commands, but it is fragile.** It ignores keys while Secure Input is on, and aborts at startup if Secure Input is on. It **re-parses its config every time the input source changes, which drops you back to the default mode** ([asmvik/skhd#281](https://github.com/asmvik/skhd/issues/281)). That matters because you switch between ABC and Thai. Upstream is in maintenance mode. [skhd.zig](https://github.com/jackielii/skhd.zig) is the maintained, drop-in replacement.
- **Raycast is a command surface, not a key layer.** Its hotkeys are global only, and it has no modes and no per-app exceptions (except for snippet expansion). Its hotkeys and settings **cannot be kept as text**: they live only in an encrypted `.rayconfig`. Snippets and Quicklinks are the exception, since they import and export as plain JSON. Its strengths are built-in commands (Lock Screen, snippets, Switch Windows, store extensions such as Do Not Disturb), and any of them can be triggered from skhd or Karabiner through `raycast://` deeplinks.
- **Do Not Disturb has no native path in any of the three.** On macOS 14 every route ends in a Shortcuts.app shortcut run with `shortcuts run`. That includes the Raycast store extension.
- **Conflict to fix first:** on this Mac, ctrl+Space is currently bound to macOS "Select the previous input source" (symbolic hotkey 60, enabled). Spotlight's cmd+Space (64) is already disabled. To get "ctrl+Space = Raycast, cmd+Space = input source", rebind 60 to cmd+Space before giving ctrl+Space to Raycast.

## Gotchas per tool

### skhd

- **Maintenance mode.** The README says only "critical issues that affect the core functionality" get fixed, and it points to [skhd.zig](https://github.com/jackielii/skhd.zig) (v0.2.0, July 2026). skhd.zig is "fully compatible with the original skhd configuration format" and adds `.shell`, `.define` process groups and command templates, mode activation with a command, hotkey sequences, and layer holds.
- **Input source switching resets modes.** skhd listens for `kTISNotifySelectedKeyboardInputSourceChanged`, then frees all modes and re-parses the config. Any mode you are in is lost when you switch ABC↔Thai ([#281](https://github.com/asmvik/skhd/issues/281)). Literal keys are resolved against `TISCopyCurrentASCIICapableKeyboardLayoutInputSource` (`src/locale.c`), so letter bindings still match under Thai. An open report says a layout change can also move focus to the main display ([#318](https://github.com/asmvik/skhd/issues/318)). Not checked whether skhd.zig has the same behaviour.
- **Secure Input.** The README says "*Secure Keyboard Entry* must be disabled for skhd to receive key-events." skhd posts a notification when Secure Input is turned on or off (`connection_handler`), so the failure is at least visible.
- **Shell cost.** Every action is `fork` → `execvp($SHELL, "-c", cmd)` (`src/hotkey.c`). With zsh and no `.zshenv` this is cheap here. Adding a heavy `.zshenv` would slow every hotkey.
- **launchd label drift.** The current README installs `com.asmvik.skhd.plist`, but this Mac runs `com.koekeishiya.skhd.plist`, and `~/Library/LaunchAgents` holds both `com.asmvik.yabai` and `com.koekeishiya.yabai`. Worth tidying before the config moves into the repo.
- Karabiner's Right Option → ⌃⇧⌥⌘ arrives in skhd as the `hyper` modifier keyword, so `hyper - x : …` works.

### Raycast

- **Hotkeys can't be versioned.** `raycast/import.mjs` can only drive deeplinks (`raycast://theme`). No documented CLI or file sets hotkeys. Exporting gives an encrypted `.rayconfig`, and importing it is a manual checklist in the UI. To keep Shortcuts as text, define the key in skhd or Karabiner and have it call `open "raycast://extensions/<owner>/<ext>/<command>?launchType=background"` ([deeplinks](https://developers.raycast.com/information/lifecycle/deeplinks)). The docs say Raycast "will ask you to confirm" a deeplinked command. Whether that is once per command or every time is unconfirmed.
- **Conflicts.** You can't reassign Raycast's own launcher hotkey. Recording a hotkey that another command already uses silently steals it from that command.
- **Hyper Key vs Karabiner.** Raycast's built-in Hyper Key sends ⌃⌥⌘ (plus ⇧ with "Include Shift"). The manual warns that other keyboard utilities like Karabiner "can intercept the key". Keep Hyper in Karabiner and leave Raycast's Hyper Key off.
- **No modes, no per-app rules.** The only per-app control is the snippet "Disabled Applications" list. 1Password and Keychain Access are on it by default.
- **Plan check:** ctrl+Space is currently macOS "Select the previous input source" on this Mac. Move that to cmd+Space (System Settings → Keyboard → Keyboard Shortcuts → Input Sources) before giving ctrl+Space to Raycast.

### Karabiner-Elements

- **Verbose JSON, GUI-owned file.** Editing `karabiner.json` by hand works because Karabiner watches the file, but the GUI rewrites it and adds dated backups. Generating it from a smaller source (for example a script, like `raycast/import.mjs`) is common practice, but it adds a build step.
- **`shell_command` semantics.** It gets a minimal environment, with no Homebrew `PATH`, so use absolute paths such as `/opt/homebrew/bin/yabai`. A second `shell_command` forcibly terminates a still-running first one, so don't chain slow scripts.
- **`open_application` vs windows.** It focuses the app, but the docs don't say which window, and it doesn't cycle windows.
- **`select_input_source`** is reliable for keyboard layouts. The docs warn only about CJKV input methods with `input_mode_id`. ABC and Thai are plain layouts.
- **Mode display** is only a notification-style message or an external bar. Variables persist until reset, so every layer needs an explicit exit.

## Unconfirmed

- Whether Raycast **app hotkeys** hide the app or cycle its windows when it is already frontmost. The manual doesn't say.
- Whether ordinary **Raycast hotkeys** fire while another app holds Secure Input. The manual only discusses Hyper Key.
- Whether the Raycast **deeplink confirmation** can be permanently suppressed per command.
- Whether **skhd.zig** still reloads the config, and so resets the mode, on input-source change.
- Latency was not measured end-to-end for any tool. The only numbers are shell and yabai startup costs.
